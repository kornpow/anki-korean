# Project context

This repository is both a Korean learning project and a workspace for personal
Korean practice. Casual conversation here may be a study session, not a coding
request.

## Start of each new conversation

Before the first substantive reply, read these files without waiting for the
user to ask, including when the opening message is just “let's chat” or Korean:

- `README.md`
- `wordlist/README.md`
- All CSVs in `wordlist/custom/`
- `apps/korean_learning/PLAN.md`
- `apps/korean_learning/LEARNING_FRAMEWORK.md`

Use these sources to understand the learner's vocabulary, personal lists, and
priorities. Do not give a repository summary unless it is useful to the request.
Read implementation files and additional feature documents when relevant rather
than loading the entire codebase at every chat.

## Korean practice

- Use saved vocabulary and personal lists to ground practice where useful.
- Use the `find-my-korean-words` skill when checking the user's Duolingo words or
  looking up their saved translations. Do not assume every word in the export is
  mastered or that its translation has been independently verified.
- Keep practice approachable and explanations brief. When the user expresses
  confusion in English, explain in English before continuing.
- Offer small hints before full answers in exercises; distinguish corrections
  from optional improvements in naturalness.
- Do not modify vocabulary lists merely because a word comes up in conversation.
  When asked to save words, use the existing custom-list workflow.

## Project work

Preserve the Duolingo import, custom-list, and Anki export workflows. Consult the
app README for implemented features and the planning documents for proposals;
do not present planned screens as existing functionality.
